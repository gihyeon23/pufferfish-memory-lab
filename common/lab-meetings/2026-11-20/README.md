## 흐름 (발표 메모)

1. **지난주 결정**: 논문 Fig 6(a) 그래프와 같게가 기준. executor 1코어
2. **왜 코드를 고치나**: 원 코드 일부가 논문 설명과 다름 → 실험을 반복해도 논문 그래프가 안 나옴
   - 예: shrink 대기 논문 2분 [p.264] vs 원 코드 약 18초 → 메모리가 논문보다 빨리 줄어듦
3. **방법**: 다른 곳을 하나씩 논문대로 고침 → 실행 → 논문 그래프와 비교 (누적)
4. **순서** A~E (코드) + F·G (실험 조건): shrink 대기 → kill 기준 → shrink 여유분 → reclaim 대상 → puff 상한 → 제출 간격 → 메모리 수요
5. **판단 지표**: PR 크기·시간, PR 첫 shrink, kill 수 (논문 1), 전체 시간 (논문 약 1866초, 그래프 역추적). 전체 시간 대비 %로 비교
6. **이번 주 결과** (각 4회, [실측])

   | 단계 | 첫 kill | PR 첫 shrink | PR 종료 | 전체 시간 | 한 줄 |
   |---|---|---|---|---|---|
   | A shrink 대기 2분 | 11~13% | 19~52% | 58~79% | 1350~1658초 | 기준선 |
   | B+E kill 기준·puff 상한 | 25~29% | 25~37% | 77~98% | 974~1178초 | kill 시각이 논문 쪽으로 |
   | C 여유분 2GB | 23~27% | 71~79% 또는 없음 | 89~96% | 1092~1141초 | 512MB는 shrink 반복 → 2GB 채택 |
   | D reclaim 대상 | — | — | — | — | Fig 6(a)에선 reclaim 안 돎 → 패치만 |
   | F 제출 간격 15초 | 25~28% | 83% 또는 없음 | 80~88% | 1094~1152초 | 효과 없음 |
   | G 수요 150% (입력 확대) | 14~18% | **52~57%** | **94~100%** | **1615~1768초** | PR 크기·첫 shrink·길이가 논문에 근접 |
   | 논문 (역추적) | 32% | 49% | 96% | 약 1866초 | |

   - 남은 차이: 논문 KM은 약 27GB(노드 23%)에 묶여 있는데 우리 KM은 2배까지 커짐 → kill이 이르고 2~3번
   - G-3: KM 사용량은 거의 전부 rss (cache 0.2GB 이하) → 측정 방식 차이 아님, KM이 실제로 더 큼
7. **정정 보고**: B를 suspension tolerance로 계획했으나, 논문상 Fig 6(a)는 기본 EJF(p.266)이고 tolerance는 EJF+S·SJF용(p.267) → B = Alg.1 kill의 11라운드 대기 제거로 변경
8. **여쭐 것**
   - G는 Table 1 "small" 입력 1/4 원칙에서 벗어남 (PR ×1.84, KM ×1.28) → 그래프 맞추기 우선으로 가도 되는지
   - 여유분은 2GB로 정함 (512MB는 shrink 반복). 노드 1/4 규모에서 2GB 그대로 둔 것 괜찮은지
